# A365 Capability Explorer

**Map any agent use case to Microsoft Agent 365.**

Live site: <https://chriswillia.github.io/a365-capability-explorer/>

> Independent project, not an official Microsoft site. Microsoft product names are trademarks of the Microsoft group of companies.

A365 Capability Explorer helps people who design, build and govern AI agents answer six questions within ten minutes: what Microsoft Agent 365 offers today, which capabilities apply to a given agent and why, where each one acts, who owns it and when it matters, what is already in place, and what would change the answer.

## Status

Preview. Built around the three requirement areas a seller discusses with a customer: Security, Governance and Observability. Includes the explorer and capability briefs, persona paths, a customer conversation guide and the Learn hub; the rule engine, scenarios, generated Scenario × Capability matrix, risk lens and "How recommendations work"; a customer-first assessment with reusable customer profiles and locally saved use cases; and discussion readouts with a portable-assessment workflow. Readouts open with the requirement areas and include numbered exhibits (nine in Executive, fourteen in Technical), the teams to involve, open questions, readiness percentages, scope-aware anatomy, current evidence and a technical appendix. Print/PDF, Markdown, JSON, clipboard summaries, seven-slide readout PowerPoint exports and one-slide canvases are available, with optional local logo co-branding. All editorial content and golden scenarios remain pending SME review; unverified licensing answers are explicitly withheld. The site asks search engines not to index it until launch. Changes appear on the live site only after a successful deployment from `main`.

Portfolios, the workshop kit and presentation mode are available. Phase 7's source watch, assessment re-run deltas, content health and launch readiness remain in development.

Previously named Control Plane Compass. The repository and GitHub Pages path now use `a365-capability-explorer`. Update bookmarks to the live URL above; browser-storage keys are unchanged.

## How to use

Start from the overview and pick your role. Sellers open the **Customer conversation guide**: five steps for running the conversation, then one section each for Security, Governance and Observability with the capabilities to discuss, the questions to ask, the teams to involve and the licensing and availability flags to check. Everything on it is computed from the catalog, so it changes when the service description does.

Browse **Capabilities** grouped by requirement area. Choose an area chip (each shows how many capabilities match the other filters), filter by product area, licensing, GCC availability or setup, and search in words a seller uses; a search that finds nothing offers matching filters. Group by requirement area or product area, switch views, and select up to four capabilities to compare. Explorer settings are kept in the URL, so bookmarks and browser history preserve them. Numbers on the overview link to the capabilities they count. Open a capability for its brief, sources, scope rules, typical scenarios and correction link.

Explore **Scenarios** for read-only illustrative results using visible canonical answers and a neutral customer. Matrix cells are generated by the same engine as scenario briefs and are grouped by requirement area. Each recommendation keeps its reasons and evidence; missing answers remain unknown. Technical adds operating-model and anatomy tables, control intensity and illustrative what-if deltas. **How recommendations work** (in the footer) answers the common questions first and keeps the rules, risk associations and unsigned golden scenarios behind one section. These pages save no assessment data and do not certify readiness, eligibility or license quantities.

Open **Assess**, name the customer and start. The cloud environment is asked in the same form, and a quick scan opens at the use case. Start from blank, a scenario or a sample; a scenario's answers are marked **assumed** until you confirm or change them, and the readout says so. Each question is written as something to ask the customer and names the requirement areas it informs. The toolbar shows the answered count, the assumed count and **Open readout**; the review step shows what applies in each requirement area. Answers, mode and section autosave locally; resume, duplicate, rename and delete assessments from the assessment home. Switching modes preserves answers. After the first assessment, the header shows **Customer: name** with a menu to reach that customer's use cases, readout, canvas and comparison.

Choose **Open readout** from a saved assessment or its review step. Results are recomputed with current content and marked **Draft for discussion**; older or incompatible answers are never silently corrected. Executive shows nine decision-oriented exhibits; Technical shows fourteen and the appendix, including what-if comparisons that do not alter saved answers. A contents list follows the reader down the page. Use **Print / save PDF** or **Download PowerPoint**, or open **More ways to share** for **Download Markdown**, **Download assessment JSON** and **Copy executive summary**. The engagement name, preparer and date can be corrected on the page. PowerPoint contains exactly seven editable slides, beginning with the requirement areas; complete detail and any shortened text are in speaker notes. Markdown always exports the full technical readout.

Optional co-branding (**Add your logo**) accepts a local PNG or JPEG up to 2 MiB and 4096 pixels per side, with a required description. The image is normalized to a bounded PNG, stored with the assessment and preserved in copied/imported assessments. JSON, PDF and PowerPoint include the logo; nothing is uploaded. Open the eleven-box Use Case Canvas for a workshop handout or a one-slide PowerPoint export, or use the blank canvas without creating an assessment. The canvas lists the in-scope capabilities under each requirement area. Success measures and the accountable owner are editable in the Full discovery. Print the canvas in landscape. Filled canvases are one-page summaries with explicitly marked shortening; complete answers remain in the readout and Markdown export.

Download a workspace JSON backup from **Assess → Backup and restore** to include every customer and assessment. To restore or transfer work, choose an exported JSON file (up to 5 MiB), review its counts, then confirm **Import as new copies**. Imports always assign new ids and preserve relationships, original answer values and original content versions. They never overwrite existing customers or assessments, even when names or ids match. Review save-status messages after importing; a storage failure leaves the imported copies in memory until saving succeeds.

Open **Compare use cases** to compare saved assessments for one customer. Select which cases to include; results always use current content without changing saved answers. Business value at least 3 and control intensity at least 50% are explicitly labeled draft planning cutoffs, not investment recommendations. Bubble areas represent ordered expected-user bands, not headcounts; unknown business values are listed but not plotted. The comparison table gives every chart value, and the capability heatmap is grouped by requirement area. Shared foundations only count platform/both capabilities used by multiple selected cases for that customer; agent decisions still apply. Readiness keeps gaps and unknowns separate. Licensing counts deduplicate capabilities, never users or license quantities. Incompatible answers are visibly excluded from calculations and can still be exported for recovery.

**Download selected portfolio JSON** includes only selected assessments and their customer. Import uses the same preview/confirmation and new-copy behavior as Assess. JSON exports above the 5 MiB import limit are blocked with an explicit message; select fewer assessments. Selection, customer filters and presentation mode are temporary, not new browser-storage records.

Open **Workshop** for a data-driven 90-minute facilitator guide, a printable requirements checklist (one page per requirement area, with a write-in column for the customer's requirement, owner and priority), paired front/back scenario cards, capability card-sort materials and a link to the blank canvas. Print the guide, the checklist or either card set separately on A4 or Letter. Card sides are paired on the same sheet for cutting/folding, not printer-dependent duplex alignment. Card summaries, scope conditions, draft labels and evidence come from the existing catalog and rules. **Enter presentation mode** on Workshop, Compare use cases, Readout or Canvas to increase type size and hide editing controls; the exit button or Escape restores the normal view. Nothing is saved by entering presentation mode.

## Run it locally

For a guided starting point, select your role on the overview. The Learn hub follows the order of a customer conversation: where Agent 365 fits, myths and facts, the concepts in one table (with a link to each capability), integration paths, related building blocks and a glossary. It separates building blocks from catalog capabilities and links source-backed explanations to official documentation. Switch to Technical for integration details. Glossary links in explanatory prose lead to definitions; focus or hover reveals a definition tooltip, and Escape dismisses it. Pending licensing answers are not licensing guidance.

Requires Node 24 (see `.nvmrc`).

```bash
npm ci
npm run lockfile:check # public npm URLs, also checked before CI installs
npm run dev          # http://localhost:5173
npm test             # unit and component tests
npm run test:e2e     # builds for both base paths, then runs Playwright and axe
```

## How to contribute

Content is data: capabilities, sources and all interface copy are YAML files in `content/`, so you can fix or add content without touching code. See [how to update content](docs/HOW-TO-UPDATE.md). For code, see the [architecture notes](docs/ARCHITECTURE.md). Use the issue tracker for corrections and ideas.

## Hosting

The site is a public GitHub Pages project site, built and deployed by GitHub Actions on every push to `main`. A published change can take up to about ten minutes to appear.

Every page with a fixed address (Capabilities, Learn, the conversation guide and so on) is also built as its own HTML file with its own title, so a shared link is answered with HTTP 200 and a link preview that names the page. An address that carries an id, such as a capability brief or a saved assessment that exists only in one browser, falls back to `404.html`, which loads the same app.

Visibility: public from the first deploy, with a `noindex` tag until launch. A privately published Pages site needs an organization on GitHub Enterprise Cloud, and an enterprise that uses Enterprise Managed Users can only publish privately. See GitHub's documentation on [changing the visibility of a Pages site](https://docs.github.com/pages/getting-started-with-github-pages/changing-the-visibility-of-your-github-pages-site).

## Privacy

Everything runs in your browser, with no cookies or analytics. Catalog searches, filters and comparison selections appear in the URL. Loading or sharing that URL exposes its query string to the host or recipient, so do not enter confidential information in catalog search. GitHub Pages logs visitor IP addresses for security purposes. See the Privacy page on the site.

Diagnostic answers, names and optional normalized logos stay in this browser profile, not URLs or network requests. Which answers came from a starting scenario and are not yet confirmed is saved with the assessment, and the header's customer shortcut reads the same saved data. They are accessible to anyone sharing that profile and disappear if site data is cleared. Storage failures retain edits in memory with visible warnings; do not close the page before saving succeeds. Conflicting tabs never intentionally overwrite a newer saved workspace. Corrupt or unsupported data is preserved for recovery until an explicit reset. JSON, Markdown, PDF, PowerPoint and copied summaries contain your answers and optional names; JSON, PDF and PowerPoint also include any selected logo. Review exports before sharing; they are not encrypted by this app. Import reads a selected file locally; nothing is uploaded.
