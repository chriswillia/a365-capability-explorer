# A365 Explorer

**Map any agent use case to Microsoft Agent 365.**

Live site: <https://chriswillia.github.io/a365-explorer/>

> Independent project, not an official Microsoft site. Microsoft product names are trademarks of the Microsoft group of companies.

A365 Explorer helps Microsoft AI sellers and Security sellers explain the value of Microsoft Agent 365 to a customer, whatever the agent is, and then map it: how the agent acts (delegated or own access), which capabilities and production guardrails apply, how it fits the customer's stack, and who needs which license and prerequisites.

## Status

Built around the jobs a seller does with a customer: pitch the value of Agent 365, map an agent (how it acts, which capabilities and production guardrails apply), fit Agent 365 to the customer's stack, and check licensing and prerequisites. Choose AI seller, Security seller or Both in the View menu to match the pitch to your role; the facts never change with it. Underneath are the requirement areas a seller discusses with a customer: Security, Governance and Observability. ## How to use

Start on Home and choose the job you are doing, or start from one of the **example agents** that look like your customer's. The header offers the same jobs (Pitch, Example agents, Map an agent, Licensing and Deploy), and a **More** menu holds everything else; the **View** menu sets Selling as and the detail level. The same steps work for any agent. To see the whole flow without entering anything, choose **Try a sample customer** on Home: it loads a fictional customer with three agents, marked **Sample data**, which you can reset or remove in one click without touching your own customers.

**Pitch.** **Pitch** shows one part at a time: **Say it**, **Prepare**, **Run the meeting** and **Value brief**. Together they give a 60-second pitch for AI sellers, Security sellers or both, the problem every agent creates in Microsoft's words, what Agent 365 gives the customer by capability, who you are talking to, answers to pushback and proof you can cite. Build a one-page **value brief** from the outcomes the customer cares about, then print or copy it; the customer name stays in memory and is never stored. The page also has a joint AI and Security plan, a one-agent proof-of-value plan and the **customer conversation guide**: five steps for running the conversation, then one closed panel each for Security, Governance and Observability with the capabilities to discuss, the questions to ask, the teams to involve and the licensing and availability flags to check. Everything in the guide is computed from the catalog, so it changes when the service description does. **Start from the customer's situation** gives an opening and the licensing path for seven situations (a customer with Microsoft 365 E5, E3 only, heavy Copilot use, building in Foundry, mostly third-party agents, frontline workers or GCC), and a picker turns up to five of the questions the capabilities suggest into a meeting agenda you can copy. The picks are not stored. Each capability page has a **Say this** card that copies what to say and what to ask.

**Map an agent.** **Map an agent** is the agent passport: answer six questions about one agent, in a seller's words, and get how it acts, the controls that matter most by requirement area, what must be in place, who to license, where it is built and the top risks. If you are not sure how it acts, three questions help you choose. It saves the customer and the agent in this browser as soon as you answer, stays out of the address (which carries only an opaque id), and feeds everything else. Stage defaults to a pilot and says it is assumed until you confirm it. Choose **Full discovery** from the passport for the longer assessment.

**Create the leave-behind.** From a saved agent, **Create leave-behind** opens a one-page summary that prints on A4 or Letter, and downloads as three slides with speaker notes. It lists everything not confirmed under **Questions to confirm**, and never states it as a fact.

**Plan the go-live.** **Deploy** has a part for each gate (before pilot, before production, as you scale) and one for a 30, 60 and 90 day plan. Each step says what to do and how to prove it works, with why it matters, where it is configured and who owns it behind one link. Choose a saved agent to see which steps are in place, which are gaps and which to confirm.

**Scope how the agent acts.** **How agents act** (in the More menu) explains delegated access, own access and an agent account in Microsoft's terms, who to license for each, what applies differently, and, for a saved assessment, how the in-scope capabilities change under each. Each capability card and page also says whether Microsoft documents it differently by how the agent acts, and says "not split by Microsoft" when it does not. Microsoft's pages describe an agent acting with its own identity, credentials or access, so the site says "own access", not "owned".

**Set production guardrails.** The assessment review and the readout show a checklist in three gates (before pilot, before production, as you scale). Each item says whether the customer's answers show it in place, a gap or still to confirm; an unanswered question is never counted as a gap.

**Fit it to the stack.** **Stack fit** (in the More menu) shows how each agent platform connects, what Agent 365 adds to the Microsoft tools a customer already runs, what stays where it is and what is new, and the platforms Microsoft lists for registry sync with their environment and observability status. Choices are kept in the URL.

**Check licensing and prerequisites.** **Licensing** has five parts: who needs a license, size the licenses, ways to license, prerequisites and take to a specialist. Together they say who needs an Agent 365 license by how the agent acts, the ways to license a user, what the Microsoft Product Terms require and where the licensing FAQ, the partner blog and the product overview describe the prerequisite differently, what each capability needs to work (one closed panel for each product area, with where it applies and the question to ask the customer), how to size the count, regulated clouds, public help with deployment, and a note to take to a licensing specialist. A **calculator** turns the counts you enter into the number of people who must be licensed, the recommended coverage and how many can add Agent 365 now, using the rules in Microsoft's FAQ and Product Terms; copy it as Markdown or download it as CSV. The numbers are not stored. It states what Microsoft is silent on and never states a price.

The **More** menu holds stack fit, how agents act, the capabilities, the Learn pages, the agent portfolio, the workshop kit and how recommendations work.

Browse **Capabilities** as cards grouped by requirement area, or switch to a table or matrix. Choose an area chip (each shows how many capabilities match the other filters), open **More filters** for where it's configured, licensing, GCC availability or setup, and search in words a seller uses; a search that finds nothing offers matching filters. Select up to four capabilities to compare. Explorer settings are kept in the URL, so bookmarks and browser history preserve them. Numbers in the catalog overview link to the capabilities they count. Open a capability for what it does, what it needs, how the agent acts, its sources, scope rules, typical scenarios and correction link.

Explore **Example agents** (also the first thing on Home) for read-only illustrative results using visible canonical answers and a neutral customer, including one for an assistant that chats for the signed-in user and also runs scheduled jobs under its own access. Each example opens on its recommended controls, with its risks and its rollout and licensing one link away; the grid that compares every example is the second part of the index. Matrix cells are generated by the same engine as the example briefs and are grouped by requirement area. Each recommendation keeps its reasons and evidence; missing answers remain unknown. Technical adds operating-model and anatomy tables, governance effort and illustrative what-if deltas. **How recommendations work** (in the footer) answers the common questions first and keeps the rules, risk associations and unsigned golden scenarios behind one section. These pages save no assessment data and do not certify readiness, eligibility or license quantities.

Open **Full discovery** (from the passport, or the customer menu in the header), name the customer and start. The cloud environment is asked in the same form, and a quick scan opens at the use case. Start from blank, a scenario or a sample; a scenario's answers are marked **assumed** until you confirm or change them, and the readout says so. Each question is written as something to ask the customer and names the requirement areas it informs. The toolbar shows the answered count, the assumed count and **Open readout**; the review step shows what applies in each requirement area and the production guardrails checklist. Answers, mode and section autosave locally; resume, duplicate, rename and delete assessments from the assessment home. Switching modes preserves answers. After the first assessment, the header shows **Customer: name** with a menu to reach that customer's use cases, readout, canvas and portfolio.

Choose **Open readout** from a saved assessment or its review step. Results are recomputed with current content and marked **Draft for discussion**; older or incompatible answers are never silently corrected. Executive shows eleven decision-oriented exhibits; Technical shows sixteen and the appendix, including what-if comparisons that do not alter saved answers. A contents list follows the reader down the page. Use **Print / save PDF** or **Download PowerPoint**, or open **More ways to share** for **Download Markdown**, **Download assessment JSON** and **Copy executive summary**. The engagement name, preparer and date can be corrected on the page. PowerPoint contains exactly eight editable slides, beginning with the requirement areas and including production guardrails; each slide's speaker notes hold what to say and the detail that slide shortens. Markdown always exports the full technical readout.

Optional co-branding (**Add your logo**) accepts a local PNG or JPEG up to 2 MiB and 4096 pixels per side, with a required description. The image is normalized to a bounded PNG, stored with the assessment and preserved in copied/imported assessments. JSON, PDF and PowerPoint include the logo; nothing is uploaded. Open the eleven-box Use Case Canvas for a workshop handout or a one-slide PowerPoint export, or use the blank canvas without creating an assessment. The canvas lists the in-scope capabilities under each requirement area. Success measures and the accountable owner are editable in the Full discovery. Print the canvas in landscape. Filled canvases are one-page summaries with explicitly marked shortening; complete answers remain in the readout and Markdown export.

Download a workspace JSON backup from **Full discovery → Backup and restore** to include every customer and assessment. To restore or transfer work, choose an exported JSON file (up to 5 MiB), review its counts, then confirm **Import as new copies**. Imports always assign new ids and preserve relationships, original answer values and original content versions. They never overwrite existing customers or assessments, even when names or ids match. Review save-status messages after importing; a storage failure leaves the imported copies in memory until saving succeeds.

Open **Agent portfolio** to compare saved assessments for one customer. Select which cases to include; results always use current content without changing saved answers. Business value at least 3 and governance effort at least 50% are explicitly labeled draft planning cutoffs, not investment recommendations. Bubble areas represent ordered expected-user bands, not headcounts; unknown business values are listed but not plotted. The comparison table gives every chart value, and the capability heatmap is grouped by requirement area. Shared foundations only count platform/both capabilities used by multiple selected cases for that customer; agent decisions still apply. Readiness keeps gaps and unknowns separate. Licensing counts deduplicate capabilities, never users or license quantities. Incompatible answers are visibly excluded from calculations and can still be exported for recovery.

**Download selected portfolio JSON** includes only selected assessments and their customer. Import uses the same preview/confirmation and new-copy behavior as Full discovery. JSON exports above the 5 MiB import limit are blocked with an explicit message; select fewer assessments. Selection, customer filters and presentation mode are temporary, not new browser-storage records.

Open **Workshop** for a data-driven 90-minute facilitator guide, a printable requirements checklist (one page per requirement area, with a write-in column for the customer's requirement, owner and priority), paired front/back scenario cards, capability card-sort materials and a link to the blank canvas. Print the guide, the checklist or either card set separately on A4 or Letter. Card sides are paired on the same sheet for cutting/folding, not printer-dependent duplex alignment. Card summaries, scope conditions, draft labels and evidence come from the existing catalog and rules. **Enter presentation mode** on Workshop, Agent portfolio, Readout or Canvas to increase type size and hide editing controls; the exit button or Escape restores the normal view. Nothing is saved by entering presentation mode.

## Run it locally

For a guided starting point, pick your role on the Learn page. The Learn hub follows the order of a customer conversation: where Agent 365 fits, myths and facts, the concepts in one table (with a link to each capability), integration paths, related building blocks and a glossary. It separates building blocks from catalog capabilities and links source-backed explanations to official documentation. Switch to Technical for integration details. Glossary links in explanatory prose lead to definitions; focus or hover reveals a definition tooltip, and Escape dismisses it. Pending licensing answers are not licensing guidance.

Requires Node 24 (see `.nvmrc`).

```bash
npm ci
npm run lockfile:check # public npm URLs, also checked before CI installs
npm run dev          # http://localhost:5173
npm test             # unit and component tests
npm run test:e2e     # builds for both base paths, then runs Playwright and axe
npm run check:public # after a build: nothing internal in the content, source or built site
```

## Hosting

The site is a public GitHub Pages project site, built and deployed by GitHub Actions on every push to `main`. A published change can take up to about ten minutes to appear.

Every page with a fixed address (Capabilities, Learn, the pitch and so on) is also built as its own HTML file with its own title, so a shared link is answered with HTTP 200 and a link preview that names the page. An address that carries an id, such as a capability brief, a leave-behind or a saved assessment that exists only in one browser, falls back to `404.html`, which loads the same app.

Visibility: public from the first deploy, with a `noindex` tag until launch. A privately published Pages site needs an organization on GitHub Enterprise Cloud, and an enterprise that uses Enterprise Managed Users can only publish privately. See GitHub's documentation on [changing the visibility of a Pages site](https://docs.github.com/pages/getting-started-with-github-pages/changing-the-visibility-of-your-github-pages-site).

## Privacy

Everything runs in your browser, with no cookies or analytics. Catalog searches, filters and comparison selections appear in the URL, as do the outcomes chosen for a value brief, the platforms and tools ticked on Stack fit and the saved assessment picked on the passport, Licensing, Deploy, leave-behind and How an agent acts pages (an identifier, not a name). Loading or sharing that URL exposes its query string to the host or recipient, so do not enter confidential information in catalog search. A customer name typed for a value brief or a licensing note, the numbers entered in the license calculator and the questions picked for a meeting agenda stay in memory on that page and are never placed in the URL or stored. The only other preference stored is the Selling as choice. GitHub Pages logs visitor IP addresses for security purposes. See the Privacy page on the site.

Diagnostic answers, names and optional normalized logos stay in this browser profile, not URLs or network requests. The passport saves the same way: the customer and agent are saved as you answer. The sample customer, if you load it, is saved there too, marked as sample data, and removing it deletes only it. Which answers came from a starting scenario and are not yet confirmed is saved with the assessment, and the header's customer shortcut reads the same saved data. They are accessible to anyone sharing that profile and disappear if site data is cleared. Storage failures retain edits in memory with visible warnings; do not close the page before saving succeeds. Conflicting tabs never intentionally overwrite a newer saved workspace. Corrupt or unsupported data is preserved for recovery until an explicit reset. JSON, Markdown, PDF, PowerPoint and copied summaries contain your answers and optional names; JSON, PDF and PowerPoint also include any selected logo. Review exports before sharing; they are not encrypted by this app. Import reads a selected file locally; nothing is uploaded.
